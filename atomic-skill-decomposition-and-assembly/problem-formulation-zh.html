研究方向

目标是解决复杂视频推理：既包括需要理解 social cue / intention / contradiction 的复杂情节推理，也包括需要跨长时间片段积累证据的 long-term video reasoning。初始想法不是提出新的 memory 存储，也不是让 8B 模型直接端到端解决长视频；而是把 teacher reasoning chain 分解成可复用的 atomic skills，再由紧凑 controller 在新问题上重新组装成可执行、可验证、可修复的 video-reasoning skill chain / graph。Memory 是长程证据组织的执行场景之一，verifier 和 repair 是让这种分解-组装能被训练与评测的支撑机制。

贡献边界：技能分解与组装，而非新的 memory system

展开完整描述

不要 claim“我们提出一种新的 memory storage 架构”，也不要把主贡献写成“又一个 memory graph”。M3-Agent、ReMEmbR、MemoryBank、HippoRAG、GraphRAG、MemGPT、LangMem 已覆盖各类 memory storage / graph / retrieval。应该 claim“我们提出一种从 teacher reasoning traces 中抽取可复用 atomic skills，并在新任务上组装 executable skill chain / graph 的框架”。memory backend 可以是 M3-Agent-like graph、FAISS / vector DB 或 event-state graph；贡献在于如何把长推理过程 factorize 成技能、如何复用这些技能、以及如何验证和修复组装出来的链。

我们到底想做什么

展开完整描述

现有 VLM 通常是 video/image + question → 自由文本 CoT → answer。这个管线有五个反复出现的问题：

  1. 中间步骤不可执行——它们是散文，不是操作。
  2. 视觉 / 记忆证据不可查——claim 无法回指到帧、clip 或 memory node。
  3. 错误无法定位——答错了也找不出失败的那一步。
  4. temporal / causal 约束容易被语言糊弄。
  5. self-correction 只能重写整段答案，而不是修复坏掉的那一步。

我们不直接复制 teacher 的整条 reasoning chain，而是把它分解成可复用 atomic skills，再为新问题组装新的可执行 skill chain / graph：

  • 转变：自由文本 reasoning chain → 可复用 atomic skills → 新的可执行 skill chain / graph。
  • 真正的目标：不是“模型会用工具”，也不是“提出新的 memory store”，而是“模型学会分解、复用、组装、执行、验证、修复推理技能”。

原子技能 = typed symbolic operator

展开完整描述

原子技能不是一句自然语言 prompt 步骤，而是一个 typed symbolic operator，带明确的输入、输出、preconditions、effects、executor、verifier 和 failure codes。Controller 学的是如何组合它们，而不是在线发明。因此 memory operation 不是 free-form writing，而是 typed、constrained、executable、verifiable 的。

技能 schema

skill = {
  name,
  input_types,
  output_types,
  preconditions,
  effects,
  executor,     # 运行该技能的 neural / tool 调用
  verifier,     # 检查结果是否 grounded 且合法
  failure_codes # 该技能可能失败的 typed 原因
}

operator 示例

DetectContact(entity_a, entity_b, time_span)
  Inputs:        Entity × Entity × TimeSpan
  Outputs:       ContactEvent
  Preconditions: visible(entity_a, time_span)
                 visible(entity_b, time_span)
  Effects:       contact_event(entity_a, entity_b, time_span)
  Verifier:      视觉接近 + 时间重叠
                 + 运动 / 状态变化
  • 小而稳定的基底：少量 typed operator 好过大量模糊工具；绝不每个任务手写一个 skill。
  • 证据优先：每个 input / output / evidence 都回指记忆或原始 clip。
  • 结构化返回：时间区间、entity id、modality、置信度、clip 指针、graph node id、短 rationale。

Skill graph（为什么比线性 CoT 强）

展开完整描述

Skill graph 的节点是原子技能，边是依赖关系。边不只是顺序，还携带 typed 依赖关系。

示例：“杯子为什么掉下来了？”

   ↓

   ↓

  • 边的类型：data、temporal、causal、evidence、memory dependency。
  • 为什么比线性 CoT / tool chain 强：多跳结构显式、可分支、可检查，并给 verifier 干净的打分边界。

  • multi-hop
  • temporal / causal
  • inspectable

Neural-symbolic 在哪里

展开完整描述

这个 framing 是 neural-guided symbolic program assembly，而不是自由想象。拆分是显式的：

  1. 符号部分：typed memory skills、preconditions / effects、skill-graph 结构、type 约束、temporal / causal 约束、symbolic executor、hard verifier。
  2. 神经部分：observer（感知 object / event / time span）、reasoner（选择 skill）、argument binder（绑定 object / timestamp / evidence / memory node）、graph assembler（生成 program）、soft verifier（判断 grounding / contact / causality）、repair policy（修复 failed program）。
  • 硬检查（符号）：type、preconditions、时间顺序、evidence pointer 是否存在。
  • 软检查（神经）：clip / memory node 是否真的支撑 claim。

三类 atomic skills + 两个横切机制

展开完整描述

保留初始想法，但把实现方式写得更硬：skills 是预定义的，不是模型在线发明的。核心任务是把 teacher reasoning chain 拟合到这个固定 atomic skill library 上，再为新问题重新组装 chain / graph。为了避免 skill taxonomy 变成一长串 memory 操作，第一篇把 skill library 收敛成三类主 skill；verification 和 repair 不单独作为 domain skill，而是横切每一类 skill 的机制。

  1. 1 — Perception-tool skills：调用 detector、tracker、OCR、ASR、VLM captioner、segmenter 等工具，把 raw video / audio / image 转成 typed observations。例：TrackEntity、DetectContact、TranscribeSpeech、LocalizeEvent、ExtractVisualEvidence。
  2. 2 — Evidence-backed memory skills：带 evidence pointer 地 store / query memory。例：StoreMemory(event, evidence)、RetrieveEvent、RetrieveEvidence、ResolveCoreference、QueryTemporalChain。关键不是“存了什么”，而是每次 store / query 都必须绑定可检查证据。
  3. 3 — Multi-hop reasoning skills：在已有 observations、evidence spans 和 memory nodes 上做组合推理。例：InferTemporalRelation、InferCausalRelation、ComparePastAndCurrentState、ComposeEvidenceChain、AnswerFromEvidence。

推荐执行流

raw video/audio
  -> perception-tool skills
  -> evidence-backed memory store/query
  -> multi-hop reasoning skills
  -> grounded answer / local repair
  • Verification 是横切机制：每类 skill 都带自己的 hard / soft verifier，而不是单独塞成第四类 domain skill。
  • Repair 是 controller 的 meta-skill：失败时替换参数、插入 missing hop、换 skill、重查 evidence 或重连 edge，而不是重新生成整条答案。
  • 第一篇最小基底：perception-tool 只保留可靠工具调用；memory skills 聚焦 evidence-backed store/query；reasoning skills 聚焦 temporal / causal / state / evidence-chain composition。

typed + verifiable memory skill 示例

单一紧凑 policy：skill assembly，而非直接推理

展开完整描述

讨论结论：不做两个分别训练的 agent，也不把 8B 表述成最终语义 reasoner。Decomposition、assembly 和 repair 是同一个紧凑 controller 的几个阶段。记忆的 write / update / merge / forget / query 是第一篇场景里的原子 skill；更一般地，controller 学的是从 atomic skill library 中选择 skill、绑定参数、组装新链，并在失败时局部修复。

保留写/读边界，而不是两个模型。当初想拆分是因为 (a) 污染和 (b) 不同时钟。(a) 靠接口纪律解决：只有带证据的观测才能 commit，推理时的假设不能写。(b) 只在 streaming 下才真正逼你分开。

  • Policy 层面：统一——reasoning / tool / memory 操作都可以落到一个 typed action space 里的 skill。
  • 执行层面：离线 = 一个 loop；streaming = 一个 policy 的两个运行时上下文。
  • 8B 做：选择 skill、绑定参数、决定检索 / 验证 / 推理步骤，并修复失败 chain / graph。
  • 8B 不做：raw video perception、开放式 causal / social reasoning，或独立裁定最终答案。
  • 监督机器：ground-truth answers、teacher demonstrations / corrections、executors、retrieved evidence 和 verifiers。
  • 上行收益：更便宜、可复用的 control policy；昂贵 teacher 用来产生 trace、辅助分解、纠正和评估，而不是永远在 inference 时完整规划。

方法主线

展开完整描述
  1. Step 1 — 收集 teacher traces。输入不是只有 answer，而是 question + context / memory state → reasoning chain / tool trace → evidence chain → answer。Trace 可以来自 teacher model、工具调用轨迹、人工示例或 benchmark evidence annotations。
  2. Step 2 — Fit trace to predefined atomic skills。给定预定义 skill library S = {s_1..s_K}，把长 chain 拟合成 typed operators：s_i = ⟨input types, output types, preconditions, effects, executor, verifier, failure_codes⟩。目标不是让模型发明 skill，也不是复刻每句话，而是把 teacher trace 解释为固定 skill 的组合。
  3. Step 3 — 建立小而稳定的 skill library。合并同义 skill，删除过窄 task-specific skill，保留能跨问题复用的 retrieval、grounding、temporal reasoning、evidence verification、answer composition 等技能。
  4. Step 4 — Assemble 新的 task-specific skill chain / graph。给定新 query q、上下文和 memory substrate M_t，8B controller 选择 skill、绑定参数，并生成 P_q = [s_1(args_1)..s_T(args_T)] 或 G_q = (V_skills, E_dependencies)。
  5. Step 5 — Execute、verify、repair。每个节点执行并返回 structured observation；hard verifier 检查 type / timestamp / evidence pointer / contradiction；失败时只修局部节点或边，而不是重写整条答案。
  6. Step 6 — Grounded answer。最终答案来自执行后的 evidence chain / memory subgraph，并在训练与评测时与 benchmark ground truth 和 evidence annotations 对齐。

训练配方（5 阶段）

展开完整描述
  1. Stage 1 — Teacher-supervised trace-to-skill fitting SFT。Teacher / tool traces 被转换为 chain → predefined typed skill sequence / graph，作为 SFT 数据。8B 先学会把自然语言推理步骤映射到固定 skill id、参数和 evidence pointer。
  2. Stage 2 — Skill-library calibration。人工锁定三类 skill 的最小基底，过滤一次性 skill；训练时不扩展 skill ontology，只学习 skill selection、argument binding、evidence binding 和 dependency edge prediction。
  3. Stage 3 — Teacher-supervised assembly SFT。给定新问题和 memory state，让 8B 生成 executable skill chain / graph，而不是自由文本 CoT。Teacher 产候选程序，hard verifier + evidence / answer anchor 过滤，只保留可执行且接地的 SFT target。
  4. Stage 4 — On-policy verified video-reasoning RL。Student 在自己的 rollout state 上采样完整 structured actions：a_t = (skill_type, tool_name, tool_arguments)。执行工具或 reasoning skill 后，由 schema validity、execution success、verifier-supported evidence / reasoning progress 和 tool cost 给 reward，用 GRPO 更新感知、检索、证据组织、social / temporal reasoning、验证、修复或停止的策略。
  5. Stage 5 — Teacher-supervised local repair。输入 bad skill chain + failure feedback → 输出 repaired chain：replace argument、insert missing skill、delete redundant node、rewire edge、change evidence span。Teacher 可以提出 repair candidate，但 candidate 必须通过 verifier / anchor 才进入训练集。

Teacher model：训练期 supervisor，而非 inference-time planner

展开完整描述

分工要清楚：teacher model 主要用于训练期生成 supervised / SFT warm-up data；8B 是最终部署的 controller；tools / verifiers 是 executor + judge，并提供 verified RL 的主 reward。Teacher 是 supervisor，不是 oracle judge，也不是 inference 时每一步都调用的 planner。

角色做什么不做什么
Teacher model生成 reasoning / tool traces；把 trace 拟合到 predefined skills；提供 SFT warm-up target 和 repair candidate / preference不当最终 verifier；不在 inference 时完整规划每一步；不单独定义真理
8B controller学习 skill selection、argument/evidence binding、dependency edge prediction、action choice、structured reflection 和 local repair不做 raw perception；不发明新 skill；不独立裁定最终答案真假
Tools / verifiers执行 perception / memory / reasoning skills；返回 observations、failure codes、hard checks、evidence / answer anchors不生成长推理链；不替代 controller 学习组合策略

Teacher-supervised data recipe

1. SFT fitting data:
   x = question + context / memory state + teacher trace
   y = predefined skill chain + args + evidence pointers + edges

2. SFT assembly data:
   x = question + memory state
   y = executable fitted skill chain / graph

3. Verified RL data:
   x = student-induced decision state s_t
   y = sampled complete action a_t = (tool_name, tool_arguments)
   r = R_format + R_exec + R_progress - R_cost

4. Repair data:
   x = bad chain + execution trace + failure code
   y = local repair patch / repaired subgraph
  • Teacher 生成，verifier 过滤：teacher 产出的 chain / repair / warm-up target 必须经过 schema、evidence pointer、timestamp、contradiction、answer / evidence anchor 等检查。
  • 主信号来自执行：工具选择和参数绑定合并成完整 action；reward 来自 tool execution + hard verifier，而不是 teacher string match 或 teacher logprob。
  • Inference 目标：8B controller 独立运行；只有低置信、verifier disagreement 或 repeated failure 时才 fallback 到 teacher。
  • 避免 teacher-compression attack：核心实验必须比较 8B SFT-only、8B + verified RL、8B + verified RL + structured repair、teacher full planning，证明 8B 学到的是可部署 control policy，而不是只背 teacher traces。

Verified Video-Reasoning RL：统一训练技能选择与参数

展开完整描述

核心修正：不要把方法讲成“memory query agent”或“tool selection 用 OPD、arguments 用 RL”。更干净的版本是统一成一个 hierarchical video-reasoning RL：每一步 controller 输出完整 skill action，a_t = (z_t, u_t, x_t)，其中 z_t 是技能类型，u_t 是具体工具 / skill name，x_t 是结构化参数。执行工具或 reasoning skill 后，由 tool execution + verifier 给 reward；teacher / OPD 只作为可选 warm-up，不是核心训练信号。

完整 action 形式

s_t -> a_t = (z_t, u_t, x_t)

z_t = skill type
u_t = tool / skill name
x_t = structured arguments

example:
{
  "skill_type": "acquire_evidence",
  "tool": "QUERY_MEMORY",
  "args": {
    "query": "red cup picked up in kitchen",
    "top_k": 5
  }
}

为什么要合并：复杂视频推理里的 skill 和 arguments 本来就不独立。QUERY_MEMORY + good query 有用，QUERY_MEMORY + bad query 没用；INFER_INTENTION + wrong social cue 会产生假解释；COMPOSE_EVIDENCE_CHAIN + missing contradiction 无法回答 Video-Holmes 式问题。统一 RL reward 的不是“多 query”，而是完整 skill action 对最终复杂视频推理是否产生可验证进展。

最小 verified reward

o_t = Execute(z_t, u_t, x_t)

R_t = R_format + R_exec + R_progress - R_cost

minimal form:
R(a_t) =
  1.0 * reasoning_progress
+ 0.1 * valid_call
- 0.05 * cost

invalid tool name / invalid schema:
  R = -1

no progress / redundant action:
  R = -0.5

answer with insufficient evidence:
  R = -1

correct refusal:
  R = +0.5

这已经是 verified RL：reward 来自工具执行、reasoning-skill execution 和 verifier，而不是 teacher string match。模型不只是学会写出像 teacher 的参数，而是学会哪些完整 skill action 能让 complex video reasoning 前进：找到关键线索、补齐 evidence role、组合跨片段证据、识别 social contradiction、验证 claim 或在证据不足时拒答。

GRPO 训练

Stage 1: SFT warm-up on teacher skill/action trajectories
Stage 2: GRPO with execution-verified rewards

For the same state s_t, sample K complete actions:
  a_1 = (QUERY_MEMORY, {"query": "...", "top_k": 5})
  a_2 = (MARK_EVIDENCE_ROLE, {"evidence": "e12", "role": "contradiction"})
  a_3 = (INFER_SOCIAL_CONTRADICTION, {"claim": "...", "evidence": [...]})
  a_4 = (ANSWER, {"text": "..."})

Execute each action:
  r_i = verifier_reward(s_t, a_i, o_i)

Relative advantage:
  A_i = r_i - mean(r_1...r_K)

Update:
  πθ(a | s)
  • 核心 claim：We train complex video-reasoning skill actions with execution-verified rewards. Instead of matching teacher-generated reasoning strings, we reward actions that are schema-valid, make verifier-supported progress toward social / temporal / long-term evidence reasoning, and avoid unnecessary tool cost.
  • SFT / OPD 的位置：teacher rollouts 只用来 initialize policy，让模型先学会合法工具调用格式；主训练信号是 verified RL。
  • 核心区别：OPD / SFT 学会 how to write valid skill actions；Verified RL 学会 which actions actually advance complex video reasoning。
  • 最小可行性：不需要 uncertainty、belief entropy 或复杂 process reward；先只 reward valid call、reasoning progress 和 cost。

一句话：把 perception / memory / social-temporal reasoning / verification 都统一看成 structured skill actions，用 execution + verifier 给 reward；OPD / SFT 只是 warm-up，真正的方法是 verified RL over complete video-reasoning actions。

Skill-chain case bank：把已验证推理链变成可检索参考

核心想法：新视频不只检索 raw evidence，也可以检索过去视频中已经验证过的 skill-chain / repair pattern，作为当前复杂视频推理的 plan prior。它不是新的 memory storage claim，而是 atomic skill decomposition 的自然延伸：把已经成功或失败后修复成功的推理程序存成案例，供新任务参考如何拆解、搜索、组织证据和修复局部失败。

训练信号从哪里来

展开完整描述

要 claim 学习贡献，就训一个紧凑 agent——memory-skill program controller。它不是最终 reasoner；它学习生成和修复 skill graph。信号按“有多真、多站得住脚”排序：

  1. 工具 + 环境反馈（免费、逐步、是骨架）：每个 typed skill 返回结构化成功/失败（检索为空、type 不匹配、重复冲突、缺失证据）。密集过程监督，零人工标注。
  2. 现有多跳 benchmark 上的 evidence-chain recall（最有区分度）：奖励正确证据链，不只是答案。prompt-only 的 72B 能用没接地的路径答对，这能抓出来。
  3. 结果 reward（答案正确性）：benchmark ground truth；稀疏但可靠的 endpoint signal。它告诉我们最终答案是否正确，但不告诉我们每个 graph step 是否正确。
  4. Teacher demonstrations and corrections：大模型提供候选 graph、repair 和 preference label。Teacher output 是监督，不是证明；需要被 ground-truth answer 和 evidence checks 过滤。
  5. On-policy correction（最干净的学习叙事）：8B 走到自己的错误状态，teacher / verifier 在这些状态上纠正 program——这让它不只是 offline distillation。
  6. 自动生成的反事实负样本：破坏好 trace（顺序错、绑定错、证据指针断、跳 hop）并训 preference。

诚实陷阱。如果只用 teacher trace 的离线 SFT 训，reviewer 会正确地说“你只是把 72B 蒸馏成 8B”。要逃出来，需要 ground-truth filtering、evidence-chain metrics、on-policy failure correction、repair success、cost/latency gains 和 transfer。

  • 训：controller（program assembly + argument binding + verification choice + repair）。
  • 不要当贡献训：memory writer——用 teacher deltas 做 SFT 然后冻结。
  • 能让训练成立的实验：冻结 teacher-planner vs 训练后的 8B program controller，工具 + memory 相同，按 answer + process metrics 打分。

与 LLM verified RL / process reward 的关系

主流 LLM verified RL 是 question → reasoning chain → answer → verifier → reward，历史上多为稀疏 outcome reward。Verifiable Process Reward 工作指出：如果中间动作能被 symbolic / algorithmic oracle 验证，oracle 就能转成 dense turn-level 监督，改善 long-horizon credit assignment——取决于 verifier 质量。

  • Executable skill chain / graph：node / edge / argument / evidence 都可验证 → node、edge、subgraph-motif、answer 级 reward。

ICLR readiness：framing 是使能条件，不是招牌

展开完整描述

这个 fix 的诚实边界。重写 framing 不提升研究本身的质量——它一行数据都没加。它是必要但不充分的：唯一作用是阻止一个好结果在 reviewer 头五分钟里被误判成“又一个 neural-symbolic / 又一个 memory graph”。预期效果约 +0.5～1 分，集中体现在不在 borderline 区间被误杀，而不是把 6 分抬成 8 分。如果两张 P0 表做不出来，framing 救不了论文；真实质量由实验决定。

Neural-symbolic = 地基，不是招牌。“neural-symbolic skill assembly” 是个老旗号（NS-CL、神经模块网络、ViperGPT、VisProg、LLM+P、program-of-thought）；用它当主标语会重新招来 novelty 归属攻击和“到底有多 symbolic？”的质疑（executor + soft verifier 都是 VLM）。把它当使能条件：正因为 memory 操作是带可检查 precondition / evidence pointer 的 typed symbolic operator，每一步才可验证——而这恰好是 failure-aware verified process RL + program repair 得以成立的前提，free-form CoT 做不到。

Headline 措辞（卖 RL + repair，把 NS 当“因为”）

Because memory operations can be cast as typed symbolic operators
with checkable preconditions and evidence pointers, every reasoning
step becomes verifiable. We exploit this to train a compact controller
with failure-aware verified process reward and program repair —
something free-form CoT cannot support.

动手实验前必须锁死的四个设计决策（这些是 framing / 设计问题，实验解决不了）：

  1. 一句话新意 = teacher reasoning chain 的 atomic-skill decomposition + 新任务上的 executable skill assembly；failure-aware verified process RL + repair 是让组装策略可训练、可评测、可纠错的机制。
  2. 三层 verifier，reward 只放 hard + anchor：hard（类型、时间戳、precondition、evidence pointer 是否存在、矛盾）+ benchmark anchor（answer correctness、evidence-chain recall）承担 reward；soft / teacher verifier 只作有噪声偏好，绝不进硬 reward。从结构上消除循环 / reward-hacking 质疑。
  3. 评测与监督解耦：生成 trace 的 teacher 不能当评分者；evidence-chain 用 benchmark 自带标注；自建 typed-trace eval 只评 hard 约束。
  4. 砍 scope 到 decomposition / assembly + query / verify / repair over teacher 已建好的 memory；store / update / merge / forget / streaming 留给第二篇。

Method spec：failure-data pipeline 与 verifier stack

展开完整描述

必须锁死的原则：teacher 主要用于生成 SFT / supervised / repair warm-up data：trace、trace-to-skill fitting、assembly target 和 repair proposal。但 teacher 不能同时当最终裁判。主 reward 只来自 tool execution + hard verifier + benchmark anchor；teacher / soft verifier 只能作为 warm-up、repair hint 或诊断信号。这样才能避免“teacher 生成 graph，teacher 又判 graph 对”的循环。

Failure-data pipeline

  1. Gold trace collection：收集能到达 ground-truth answer 且通过 evidence checks 的 teacher / tool traces，并转成 typed skill chain / graph，作为 fitting / assembly SFT 数据。
  2. Synthetic corruption：自动破坏一个局部节点或边：wrong entity、wrong timestamp、missing evidence pointer、skipped hop、wrong temporal order、unsupported answer step。优点是失败位置和 gold repair 可控。
  3. Natural student failure：让 8B controller on-policy rollout；执行后由 hard verifier / benchmark anchor 标出失败节点、失败边或 unsupported evidence。优点是真实，能证明模型在修自己的错误。
  4. Counterfactual distractor：构造相似 entity、相近时间段、相似事件或相似 evidence span，专门制造 retrieval / grounding / coreference 混淆。
  5. Failure code assignment：每个失败样本必须带一个主 failure code，例如 WRONG_ENTITY、BAD_TIMESTAMP、MISSING_EVIDENCE、SKIPPED_HOP、CONTRADICTION、INVALID_PRECONDITION。
  6. Repair target generation：teacher / human 只给 repair candidate / patch supervision；candidate 必须重新执行，并通过 hard verifier + benchmark anchor 才能作为 positive repair target。
  7. Audit：对 natural failures、teacher-generated repairs、soft-verifier disagreements 做人工抽检；优先抽检高 reward、低 evidence support、或 verifier disagreement 的样本。

  • Repair acceptance rule：repair 后的 chain 必须 executable，并同时满足 hard validity + benchmark anchor；teacher 赞同但 hard checks 失败的 repair 不能当正样本。
  • 主 claim：不是“teacher 说这条链更好”，而是“局部 repair 后，typed constraints、evidence grounding 和 answer/evidence anchor 同时改善”。

Structured reflection / repair over fitted skill chains

展开完整描述

关键边界：reflection 不是让模型自由写一段“我哪里错了”。我们采用 verifier-grounded structured reflection：执行 fitted skill chain，收集每个节点的 verifier output，再把反思限制为 failure localization、failure code assignment、root-cause tracing 和 repair operator selection。

与近期 verifiable RL / self-correction 工作的关系。RLVR / GRPO / Visual-RFT 说明：当 reward 可验证时，rollout + group-relative / RL post-training 能提升推理或视觉任务。SCoRe / multi-turn self-correction 说明：修正能力最好在模型自己的 on-policy correction traces 上训练，而不是只靠离线 SFT。但我们的任务不能照搬自然语言 self-correction；因为 skill library、executor、evidence pointer 和 hard verifier 都是结构化的，所以 repair 应该是局部 patch，而不是重写整条 reasoning。

Algorithm：Trace-to-skill fitting

Input: teacher trace T, predefined skill library S, evidence annotations E
Output: fitted skill graph G

1. Normalize T into candidate action spans.
2. For each span, select skill_id from S.
3. Bind arguments, evidence pointers, and output variables.
4. Add dependency edges between skill outputs and later inputs.
5. Execute/check each skill when possible.
6. Keep G only if hard checks + answer/evidence anchors pass.

Algorithm：Structured reflection and local repair

Input: fitted graph G, execution trace R, verifier outputs V
Output: repaired graph G'

1. Locate failed node/edge using hard verifier + benchmark anchor.
2. Assign failure_code.
3. Trace upstream dependencies to identify root cause.
4. Select repair_operator from fixed set.
5. Generate local graph patch, not a full-chain rewrite.
6. Re-execute affected subgraph.
7. Accept patch only if hard checks and evidence/answer anchors improve.

用实质 reframe 提升真实质量(及它需要的实验)

展开完整描述

两种 reframe——只有一种能提升真实质量。

  1. 营销式 reframe(换说法):换 headline、把 neural-symbolic 降级、写更漂亮的 positioning。只改变别人的观感 → 不提升真实质量(见卡片 023)。
  2. 实质式 reframe(重定义研究问题 / 贡献单元):改变你测什么、claim 什么,从而改变你做哪些实验 → 这是除了跑实验之外唯一能提升真实质量的杠杆。没有免费午餐:它重定向努力,不替代努力——但能把同样的工作量瞄准更高的天花板。

四个实质 reframe(按杠杆排序):

  1. 从"做一个系统"到"研究一个现象"(最大杠杆)。不是"这个系统能做 memory reasoning",而是"什么时候、为什么 从失败的 skill chain 学修复 会胜过整链蒸馏 / SFT?"把工程论文变成科学论文,产出是 finding 而不是 leaderboard 名次。
  2. 从"赢 benchmark"到"证明一个性质(property)"。瞄准 只有 typed-verifiable-repair 结构才能带来的 transfer / compositional generalization / reliability。property-centric framing 强迫你做出产生 principle 的实验——这是从 recipe 到 principle 的路。
  3. 从"repair 是一个阶段"到"repair 是中心对象"。把 bad program + feedback → repaired program 作为全篇深入研究的核心机制,而不是被三类 skill taxonomy 稀释。这是最不易被对标掉的 novelty;要集中。
  4. 从"自建 eval 是负担"到"评测协议是一等贡献"。"第一个能评分 memory-operation correctness + repair 的协议。"它的质量独立于方法是否赢 → 一条不依赖实验运气的质量下限。

推荐组合:主 reframe = #1 + #3(围绕 repair 机制的现象研究);#2 作为关键实验(transfer 证明);#4 作为质量保底(开源评测协议)。

需要加实验吗?需要——作为重定向,不是堆量。P0 那一对(卡片 023)仍是 go/no-go 闸门;在其上加下面这些 principle 级实验;砍掉任何只是"再来一张胜负表"的东西。净增约 +4,但要有纪律(每个 transfer / streaming 设置都很贵)。

  • 顺序:P0 闸门 → repair dose–response(#1/#3)→ transfer(#2)→ 可靠性 + 协议开源(#4)。

从旧 Video_Skills 实现中提炼的设计教训

展开完整描述

背景：旧 Video_Skills repo 实现了一个 Phase-1 deterministic substrate（14 个 curated atomic skills、7 个 canonical typed objects、三层 memory、6 个 verifier checks、deterministic harness、rule-based controller、online serving loop；58 个测试全绿）。后续实验中许多代码跑不通或效果不好，但以下 design insights 经过实践检验仍然成立，应直接吸收进当前方案。

  1. 锁死 wire format，禁止 ad hoc dict。旧 repo 定义了 7 个 canonical typed objects（GroundedWindow、EvidenceBundle、HopGoal、AtomicStepResult、VerificationResult、AbstainDecision、ReasoningTrace）作为所有模块之间唯一合法的传递格式。当前 story 一直说"typed, constrained, executable, verifiable"但没定义具体传什么。需要借鉴：第一篇必须锁一组 canonical objects，特别是 EvidenceRef 的最小字段（modality, time_span, entities, provenance, confidence）和 AtomicStepResult 的 failure_mode enum。旧 repo 把 typed objects 做得太重（很多 field 实践中用不到），教训是只保留运行时真正检查的字段。
  2. "Stable memory, evolving reasoning" 分层经实践验证。如果 memory 和 skills 同时演化，training 信号会退化。旧 repo 明确记录："if the bank were allowed to grow freely while the controller was being trained, the controller's action space would shift mid-training and the GRPO reward signal would degrade." 当前 story 应直接引用这条教训来 justify"第一篇 memory 操作用 teacher-built + freeze"的 scope 决策。
  3. Skill 必须在定义时就声明 verification rule 和 failure modes。旧 repo 每个 SkillRecord 在创建时必须带 verification_rule 和 failure_modes，而不是执行后再发明 verifier。实践经验是：如果 verification rule 不跟 skill 一起定义，后面加 verifier 时会发现很多 skill 的 output 根本没有足够的结构让 verifier 检查。
  4. next_action escalation 比自由文本 repair 更实际。旧 verifier 返回 next_action ∈ {continue, retry, broaden, switch_skill, abstain}，用 severity ordering 聚合。自由文本的"模型反思哪里错了"在实际中不可靠。建议：当前 story 的 10 种 repair operators 第一篇只保留 5-6 种（旧的 5 种 + INSERT_SKILL），其余等有 on-policy failure 数据后再加。
  5. 14 个 v1 atomics 暴露了 skill 粒度问题。旧 repo 有 14 个 atomic skills，但实践发现：(a) identify_question_target 和 decompose_into_subgoals 不应该是 skill，它们是 controller 的内部动作；(b) check_evidence_sufficiency 和 decide_answer_or_abstain 也不该是 skill，而是 verification / decision 的横切机制。当前 story 的"verification 和 repair 是横切机制，不是第四类 skill"这个决定被旧 repo 经验 confirm 了。真正可复用的 reasoning skills 只有 6-7 个，给当前"最小稳定基底"提供了 empirical lower bound。
  6. Evidence-first 硬约束：claim 没有 evidence 就必须 abstain。旧 repo 的 Contract Rule #3："Every claim either has a non-empty EvidenceBundle or a verifier action of abstain." 每一步用 validate_atomic_step() 强制执行。当前 story 应把这条写成 hard constraint：skill output 是 claim 类型时，要么绑 evidence refs，要么 abstain；裸 claim 被 hard verifier 直接拒绝。
  7. 三层 memory 的实际经验：episodic 最可靠，semantic 和 state 很难填。Episodic memory（事件 + 时间 + 参与者 + evidence refs）直接来自 perception output，最 grounded。Semantic memory（抽象概括）和 state memory（belief + spatial）依赖 72B/32B 的高质量输出，如果 perception 不准这两层就很脏。建议：第一篇把 memory 限制为 episodic + evidence layer 为主。
  8. Harness 作为 deterministic interpreter 是正确的架构。Controller 只管选 skill + 绑参数；执行和 side effect 由 harness 控制——保证 skill execution 可重放、trace 完整、memory write 可审计。当前 story 的方法主线里"Execute and verify"其实就是 harness 的角色，但没有显式命名。

旧实现中失败的教训（反面确认当前方向）：

  • Rule-based controller 不够——confirm 了训练 8B controller 的必要性。
  • Lexical retrieval 不够用——第一篇应从一开始用 embedding-based retrieval。
  • Hand-authored skills without trace fitting 太刚性——不能适配新问题类型，confirm 了 trace-to-skill fitting 的价值。
  • 没有 repair 机制导致 verifier 说 fail 后只能 abstain——旧 repo 的 switch_skill 和 broaden 经常不够用，confirm 了 local repair 的必要性。

一句话：旧 repo 最大的价值不是代码本身，而是它用可运行的实现回答了当前 story 里最模糊的几个设计问题（wire format、inference 流程、skill 粒度、memory 分层、verification 硬约束），同时它的失败经验反面确认了当前方向（trained controller、trace fitting、local repair）的必要性。

Trace-to-skill fitting：从 demonstrations 诱导技能基底

展开完整描述

更新后的立场：核心方法是 Trace-to-Skill Fitting，不是开放式在线发明技能。我们不应该声称一个手写 12-skill 列表天然普适，也不应该让 35B 模型自由创造或 patch atomic skills。更稳的做法是：demonstrations 诱导候选 operation clusters；controller 训练前选择一个紧凑 typed atomic basis 并冻结；之后可以从反复验证成功的子图中发现 composite motifs，但这些 motif 必须能展开回冻结的 atomic basis。

方法流程

teacher / tool / evidence demonstrations
  -> trace segmentation
  -> operation-intent clustering
  -> candidate operation ontology
  -> coverage / confusion / cost selection
  -> frozen typed atomic basis
  -> trace-to-skill fitting
  -> controller training over frozen basis
  -> verified composite motif mining
层级是否可发现何时发生安全规则
Atomic skill basis由 demonstrations 诱导，然后冻结controller 训练前必须有 typed I/O、executor、verifier、failure codes
Composite motif可以反复出现且验证通过后必须展开成冻结 atomics；不能携带当前视频事实
Atomic ontology revision极少，离线发生大版本之间需要 replay 提升、低 confusion、跨 benchmark 支持
在线新增 atomic skill不允许v1 永不发生避免 action-space drift 和不可验证的 skill pollution

如何回应 reviewer 质疑。12-skill 版本不应被辩护为手工设计出来的正确答案，而应被辩护为 induced candidate operations 上的 elbow point：trace-step coverage 高、skill confusion 低、execution / verifier pass rate 高、tool cost 合理。24-skill 版本保留为 fitting 和 ablation 的候选 ontology；在线 controller 只看到被选出的紧凑 basis。

Composite 示例。反复出现的 alibi-contradiction trace 不应该变成新的 primitive，而应成为一个 verified motif：

ResolveAlibiContradiction(person, claim)
  = extract_dialogue_claim
  + retrieve_temporal_neighborhood
  + localize_clue
  + mark_evidence_role

  • Atomic skills 是 primitives：小、typed、可执行、可验证，并在 controller 训练期间冻结。
  • Composite skills 是可复用 motifs：可从 demonstrations / successful rollouts 中发现，但必须可展开、可检查、可局部修复。
  • 35B / frontier teachers：可以生成 traces 或候选 alignment，但是否接受 fitted graph 由 executor + verifier + benchmark anchor 决定。
  • 核心 claim：把自由文本 multimodal traces 转成可执行、经 verifier 过滤的 skill graphs，而不是蒸馏 teacher CoT 字符串。

可选：verified reasoning motifs 作为组装先验

展开完整描述

决策：第一篇不需要把 composed skills 做成核心机制。视频推理最需要的是 atomic skill graph assembly + evidence-grounded verification + local repair。可复用的组合模式有价值，但只应作为可选的 assembly / repair prior，而不是新的 primitive、不是在线 action、也不是证据来源。

视频推理里的主要失败通常不是“缺一个 macro-skill 名字”，而是证据片段找错、entity / speaker 绑定错、时间顺序错、claim 没有 evidence pointer、缺 bridge evidence、social / causal inference 没有被当前视频支撑。这些问题更应该由 atomic nodes、typed dependencies、evidence pointers、verifier checks 和 local repair 解决。

motif 的正确角色

Question: "Why was the alibi inconsistent?"
  -> retrieve a verified motif:
       claim -> contradiction evidence -> linking action -> verify
  -> instantiate an atomic skill graph on the current video
  -> execute, verify, and repair the expanded atomic nodes

motif 示例

ResolveAlibiContradiction(person, claim)
  expands to:
    extract_dialogue_claim
    retrieve_temporal_neighborhood
    localize_clue
    mark_evidence_role
    compose_evidence_chain
    infer_social_contradiction
    verify_evidence_supports_claim
  • 不是 primitive：motif 不是新的 atomic skill，也不应该扩大 controller 的在线 action space。
  • 不是证据：motif 不携带旧视频事实；当前答案仍必须由当前视频证据支撑。
  • 必须可展开：执行前，每个 motif 都必须展开成冻结的 atomic skill nodes 和 typed edges。
  • 在 motif 下层修复：执行失败时修展开后的 node / edge / argument，而不是修 macro label。
  • 最适合的用途：降低 planning cost、提升 transfer、提供 repair prior，例如 MISSING_LINKING_ACTION -> query earlier segment for person-object interaction。

推荐表述：我们不依赖开放式技能创造，而是在紧凑 atomic skill basis 上组装任务特定的可执行图。从成功 traces 中挖掘出的可复用 reasoning motifs 只作为组装先验，并且在执行和验证前必须展开成 atomic skill graph。
