研究方向

我们不提出新的 memory 存储，也不声称 8B 模型独立解决长程视频推理。我们训练一个紧凑 controller，让它组装和修复可执行的 memory-skill graph，把 teacher demonstrations、工具执行、验证、检索和 benchmark ground-truth answer feedback 组织到长期多模态记忆之上。

我们到底想做什么

展开完整描述

现有 VLM 通常是 video/image + question → 自由文本 CoT → answer。这个管线有五个反复出现的问题：

  1. 中间步骤不可执行——它们是散文，不是操作。
  2. 视觉 / 记忆证据不可查——claim 无法回指到帧、clip 或 memory node。
  3. 错误无法定位——答错了也找不出失败的那一步。
  4. temporal / causal 约束容易被语言糊弄。
  5. self-correction 只能重写整段答案，而不是修复坏掉的那一步。

我们用可执行的神经符号 memory-skill graph 替代自由文本 reasoning chain：

  • 转变：自由文本 reasoning chain → 可执行的神经符号 memory-skill graph。
  • 真正的目标：不是“模型会用工具”，而是“模型学会在 memory 上组装、执行、验证、修复程序”。

原子技能 = typed symbolic operator

展开完整描述

原子技能不是一句自然语言 prompt 步骤，而是一个 typed symbolic operator，带明确的输入、输出、preconditions、effects、executor、verifier 和 failure codes。Controller 学的是如何组合它们，而不是在线发明。因此 memory operation 不是 free-form writing，而是 typed、constrained、executable、verifiable 的。

技能 schema

skill = {
  name,
  input_types,
  output_types,
  preconditions,
  effects,
  executor,     # 运行该技能的 neural / tool 调用
  verifier,     # 检查结果是否 grounded 且合法
  failure_codes # 该技能可能失败的 typed 原因
}

operator 示例

DetectContact(entity_a, entity_b, time_span)
  Inputs:        Entity × Entity × TimeSpan
  Outputs:       ContactEvent
  Preconditions: visible(entity_a, time_span)
                 visible(entity_b, time_span)
  Effects:       contact_event(entity_a, entity_b, time_span)
  Verifier:      视觉接近 + 时间重叠
                 + 运动 / 状态变化
  • 小而稳定的基底：少量 typed operator 好过大量模糊工具；绝不每个任务手写一个 skill。
  • 证据优先：每个 input / output / evidence 都回指记忆或原始 clip。
  • 结构化返回：时间区间、entity id、modality、置信度、clip 指针、graph node id、短 rationale。

Skill graph（为什么比线性 CoT 强）

展开完整描述

Skill graph 的节点是原子技能，边是依赖关系。边不只是顺序，还携带 typed 依赖关系。

示例：“杯子为什么掉下来了？”

   ↓

   ↓

   ↓

  • 为什么比线性 CoT / tool chain 强：多跳结构显式、可分支、可检查，并给 verifier 干净的打分边界。

  • multi-hop
  • temporal / causal
  • inspectable

Neural-symbolic 在哪里

展开完整描述

这个 framing 是 neural-guided symbolic program assembly，而不是自由想象。拆分是显式的：

  1. 符号部分：typed memory skills、preconditions / effects、skill-graph 结构、type 约束、temporal / causal 约束、symbolic executor、hard verifier。
  2. 神经部分：observer（感知 object / event / time span）、reasoner（选择 skill）、argument binder（绑定 object / timestamp / evidence / memory node）、graph assembler（生成 program）、soft verifier（判断 grounding / contact / causality）、repair policy（修复 failed program）。
  • 硬检查（符号）：type、preconditions、时间顺序、evidence pointer 是否存在。
  • 软检查（神经）：clip / memory node 是否真的支撑 claim。

五类 memory skills

展开完整描述

基底要小，且是 memory-operating（不是普通 video skills）。分五类：

  1. A — Perception-to-memory（把观察写入记忆）：ExtractEntity、ExtractEvent、ExtractState、ExtractEvidence、StoreMemory。→ raw video/audio → 结构化 memory records。
  2. B — Memory query（从记忆中查找）：RetrieveEntity、RetrieveEvent、RetrieveState、RetrieveEvidence、QueryTemporalChain、QueryRelationalNeighborhood。→ query → 相关 memory subgraph / clips / evidence。
  3. C — Update / consolidation（更新、合并、压缩）：ResolveCoreference、MergeDuplicateMemory、UpdateState、ConsolidateEpisodes、CompressSubgraph。→ 减少重复、保持长期一致性、形成更高层语义记忆。
  4. D — Verification（记忆是否可信）：VerifyEvidence、VerifyTemporalOrder、VerifyStateTransition、CheckContradiction、CheckMemoryGrounding。→ 防止 hallucinated / stale memory 和错误 entity linking。
  5. E — Memory reasoning（基于记忆推理）：InferTemporalRelation、InferCausalRelation、ComparePastAndCurrentState、FindPrecedingCause、ExplainEventFromMemory、AnswerFromEvidence。→ memory subgraph → answer / explanation / action decision。
  • 关键：它们是 memory-operating skills，不是普通 video skills。
  • 感知 / 关系 operator（如 TrackEntity、DetectContact）作为 executor 存在于 A 类和 E 类内部。

单一紧凑 policy：program assembly，而非直接推理

展开完整描述

讨论结论：不做两个分别训练的 agent，也不把 8B 表述成最终语义 reasoner。Decomposition、assembly 和 repair 是同一个紧凑 controller 的几个阶段。记忆的 write / update / merge / forget / query 是同一个 typed action space 里的原子 skill。被学习的贡献是一个生成并修复 typed memory-skill programs 的单一 policy。

保留写/读边界，而不是两个模型。当初想拆分是因为 (a) 污染和 (b) 不同时钟。(a) 靠接口纪律解决：只有带证据的观测才能 commit，推理时的假设不能写。(b) 只在 streaming 下才真正逼你分开。

  • Policy 层面：统一——memory 操作就是一个 typed action space 里的 skill。
  • 执行层面：离线 = 一个 loop；streaming = 一个 policy 的两个运行时上下文。
  • 8B 做：选择 skill、绑定参数、决定检索 / 验证步骤，并修复失败 graph。
  • 8B 不做：raw video perception、开放式 causal / social reasoning，或独立裁定最终答案。
  • 监督机器：ground-truth answers、teacher demonstrations / corrections、executors、retrieved evidence 和 verifiers。
  • 上行收益：更便宜、可复用的 control policy；昂贵 teacher 用来示范、纠正和评估，而不是永远在 inference 时完整规划。

方法主线

展开完整描述
  1. Step 1 — 维护一个外部 memory substrate（graph，或 vector+graph hybrid）：M_t = (V_t, E_t, X_t)，其中 V_t = entity / event / state / evidence 节点，E_t = temporal / relational / support 边，X_t = 原始 evidence pointer、embedding、metadata。
  2. Step 2 — 定义神经符号 memory skills S_mem = {s_1..s_K}，每个 s_i = ⟨input types, output types, preconditions, effects, executor, verifier⟩。
  3. Step 3 — 组装 task-specific memory programs。给定 query q，8B controller 不直接回答，而是生成 program P_q = [s_1(args_1)..s_T(args_T)] 或 graph G_q = (V_skills, E_dependencies)。
  4. Step 4 — 执行并验证。每一步读写 memory 并被检查：M_t, state_i = Execute(s_i, M_t, state_{i-1})；Verify(s_i, M_t, evidence)。
  5. Step 5 — 答案基于 memory 证据：最终答案来自 retrieved memory subgraph + 原始 evidence pointer，并在训练 / 评测时与 benchmark ground truth 对齐检查。

训练配方（5 阶段）

展开完整描述
  1. Stage 1 — 在 teacher memory-operation traces 上 SFT。Teacher 产生 question + memory state → skill graph → evidence chain → answer。只保留能到达 ground-truth answer 且通过基本 evidence / format 检查的 traces。8B 学 DSL 格式、decomposition、argument binding 和 evidence citation——不是学自由式视频推理。
  2. Stage 2 — Subproblem curriculum。拆成可验证 subproblem（检索、coreference、state comparison、temporal / causal relation、evidence verification）。先训短 program。
  3. Stage 3 — 8B rollout 多个 memory program。P_1..P_K ~ π_θ(P | q, M_t)；不同 program 检索不同事件、绑定不同实体、引用不同 evidence，或选择不同 verification path。
  4. Stage 4 — 用 ground truth + process feedback 打分。用 answer correctness 作 endpoint anchor；有 evidence-chain 标注时用 evidence recall；再用 hard validity checks 和 teacher / verifier feedback 作为有噪声的过程信号。目标是 valid executable program > invalid / unsupported program，而不只是 correct > wrong answer。
  5. Stage 5 — 局部修复 / learn from failures。输入 bad program + failure feedback → 输出 repaired program：replace argument、insert missing node、delete redundant node、rewire edge、change evidence span。

Action-level OPD：蒸馏工具选择，而非 token

展开完整描述

核心修正：不需要对每个生成 token 取 teacher log-prob。我们的对象是 tool-calling / harness controller；每一步真正需要学习的是在当前 decision state 下该选哪个 memory/tool/action。因此 OPD 应该定义在 action distribution 上，而不是 vocabulary token distribution 上。

从 token OPD 改成 action OPD

token-level OPD:
  y_t ∈ vocabulary
  teacher gives p_T(y_t | prefix)
  student matches token distribution

action-level OPD:
  a_t ∈ A(s_t)
  A(s_t) = {retrieve, verify, repair, retry, reflect, stop, ...}
  teacher gives p_T(a_t | s_t)
  student matches action distribution

这里的 s_t 来自 student 自己的 rollout：question + memory state + previous tool calls + observations + verifier feedback。所以它仍然是 on-policy：训练 states 不是 teacher demonstration，而是 student 在自己的 tool-calling chain 里走出来的状态。

训练流程

For each task x:
  τ ~ π_student                  # student rolls out a harness trajectory
  for each decision state s_t in τ:
    construct candidate action set A_t
    ask teacher to choose among A_t with constrained one-letter output
    obtain teacher logprobs over option letters
    update student/controller to match teacher action distribution

更可靠的 teacher signal：不要让 teacher 自报 0-1 verbal score；LLM 的分数校准会随 prompt 和 state 漂移。更干净的做法是把候选动作映射成单 token 选项，让 teacher 只输出一个字母，并读取这些字母的 logprob / top_logprobs。

约束式 action choice

Choose exactly one option:
A. retrieve_memory
B. verify_evidence
C. repair_program
D. retry_with_new_query
E. ask_for_clarification
F. final_answer

Answer with only one letter.

Action OPD loss

π_T(a | s_t) = softmax(logp_T(letter_a | s_t) / τ_T)
π_S(a | s_t) = softmax(logp_S(letter_a | s_t) / τ_S)

L_action_OPD =
  E_{τ ~ π_S} Σ_t w_t · KL(π_T(. | s_t) || π_S(. | s_t))
  • Novelty：distill test-time control policy，而不是 token reasoning traces。
  • API 友好：teacher 只需要短输出和 top_logprobs；不依赖同 tokenizer，也不需要完整 token-level CoT logits。
  • 稳定性纪律：action label 用单 token（A/B/C/D/E/F），训练时随机打乱 option order，读取所有候选字母的 top-k logprobs；缺失候选用 floor logprob。
  • 重要状态可重复校准：对同一个 s_t 用不同 option order 重复数次，平均映射回真实 action 后的 logprobs，降低位置偏置。
  • 与 SOD / repair 结合：w_t 可由 action divergence、observation quality、verifier confidence 和 failure severity 决定；JSD 可作为比 KL 更稳的 divergence 诊断。

一句话：Action-Level On-Policy Distillation for Test-Time Agent Control：让大 teacher 在 student-induced states 上给出工具选项的 logprob distribution，训练紧凑 controller 学会何时检索、验证、修复、重试或停止。

Memory-operation reward 与修复

展开完整描述

Memory program reward 草图

R(P) =  retrieval_correctness
      + evidence_support
      + temporal_consistency
      + state_consistency
      + memory_update_validity
      - contradiction
      + answer_correctness

重要解释。answer_correctness 是 benchmark ground-truth endpoint；它负责过滤和锚定 rollout。其他项是过程信号，用来解释一个 program 为什么成功或失败。它们不要求 8B 独立裁定最终答案。

偏好对（P_good > P_bad）

P_bad:  因 entity confusion 检索到错误的人
P_good: ResolveCoreference -> RetrieveEvent -> VerifyEvidence -> Answer

P_bad:  存入一个没有 evidence pointer 的 ungrounded event
P_good: ExtractEvent -> VerifyEvidence -> StoreMemory

局部修复示例

Failure:
  RetrieveEvent 返回了目标事件之后的事件，
  违反 temporal constraint。
Repair:
  加 QueryTemporalChain + 过滤目标时间戳之前的事件。
  • Novelty：从失败的 memory operations 中学习，而不只是从错误答案中学习。
  • 精确学习目标：bad program + feedback → repaired program，不是 video → answer。

训练信号从哪里来

展开完整描述

要 claim 学习贡献，就训一个紧凑 agent——memory-skill program controller。它不是最终 reasoner；它学习生成和修复 skill graph。信号按“有多真、多站得住脚”排序：

  1. 工具 + 环境反馈（免费、逐步、是骨架）：每个 typed skill 返回结构化成功/失败（检索为空、type 不匹配、重复冲突、缺失证据）。密集过程监督，零人工标注。
  2. 现有多跳 benchmark 上的 evidence-chain recall（最有区分度）：奖励正确证据链，不只是答案。prompt-only 的 72B 能用没接地的路径答对，这能抓出来。
  3. 结果 reward（答案正确性）：benchmark ground truth；稀疏但可靠的 endpoint signal。它告诉我们最终答案是否正确，但不告诉我们每个 graph step 是否正确。
  4. Teacher demonstrations and corrections：大模型提供候选 graph、repair 和 preference label。Teacher output 是监督，不是证明；需要被 ground-truth answer 和 evidence checks 过滤。
  5. On-policy correction（最干净的学习叙事）：8B 走到自己的错误状态，teacher / verifier 在这些状态上纠正 program——这让它不只是 offline distillation。
  6. 自动生成的反事实负样本：破坏好 trace（顺序错、绑定错、证据指针断、跳 hop）并训 preference。

诚实陷阱。如果只用 teacher trace 的离线 SFT 训，reviewer 会正确地说“你只是把 72B 蒸馏成 8B”。要逃出来，需要 ground-truth filtering、evidence-chain metrics、on-policy failure correction、repair success、cost/latency gains 和 transfer。

  • 训：controller（program assembly + argument binding + verification choice + repair）。
  • 不要当贡献训：memory writer——用 teacher deltas 做 SFT 然后冻结。
  • 能让训练成立的实验：冻结 teacher-planner vs 训练后的 8B program controller，工具 + memory 相同，按 answer + process metrics 打分。

与 LLM verified RL / process reward 的关系

展开完整描述

主流 LLM verified RL 是 question → reasoning chain → answer → verifier → reward，历史上多为稀疏 outcome reward。Verifiable Process Reward 工作指出：如果中间动作能被 symbolic / algorithmic oracle 验证，oracle 就能转成 dense turn-level 监督，改善 long-horizon credit assignment——取决于 verifier 质量。

我们的 insight：自由文本 CoT 的 step 不稳定、难验证；memory-skill 的 step 是 typed operator，天然适合过程级 verified reward。

  • 自由文本 CoT：step 难定义 / 难验证。
  • MemorySkillGraph：node / edge / argument / evidence 都可验证 → node、edge、subgraph-motif、answer 级 reward。
相关工作
  • RLVR / Tülu 3 — 从可验证 reward 做 RL；verifier 驱动 post-training 的骨架。
  • Process Reward Models — step 级 reward；支撑按 node/edge 打分。
  • GRPO（DeepSeekMath） — 在 rollout 上做 group-relative optimization；抬到 program 级 rollout。
  • DPO — preference 优化；“valid > invalid” program 训练的基础。

从近期 VLM reasoning / post-training 的启发

展开完整描述
  1. Visual-RFT / VLM-R1：multiple rollouts + verifiable reward + GRPO 优于仅 SFT；task-specific rule-based reward（如 IoU）。→ 采样多个 memory program、执行 / 验证、对 program policy 做 GRPO，设计 skill-specific verifier。
  2. Point-RFT / grounded CoT：text-only CoT 导致 hallucination；grounded CoT 把 ChartQA 从 70.88% 提到 90.04%。→ 不是每句话绑定，而是每个 skill node 的 input / output / evidence 都绑定。
  3. Critic-V：Reasoner + Critic；DPO 训的 critic 抓 VLM 错误。→ 我们的 critic 在 node / edge / evidence 级运作。
  4. Self-correction / learn-from-failure：必须被训练，不能只靠 prompt。→“wrong answer → correct answer”变成“failed memory program → repaired program”。
  5. PRM / VPR：dense verifier-grounded reward 改善 long-horizon credit assignment。→ memory skills 天然提供 step boundary。
相关工作
  • Visual-RFT — 为 LVLM 做可验证 reward RFT；program-level rollout 模板。
  • VLM-R1 — R1 风格的 VLM RL；可验证 reward post-training 基础设施。
  • Critic-V — 多模态推理的 Reasoner + Critic；node/edge/evidence 级 critique。

与 M3-Agent 的区别 + related-work map

展开完整描述

M3-Agent = 构建多模态长期 memory graph + retrieve + iterative thinking/control。我们 = given / 维护一个 memory substrate + 定义神经符号 memory skills + 组装可执行 memory programs + 验证 query/store/reasoning 步骤 + 从失败的 memory operations 中训练。

M3-Agent 更关注如何构建和检索多模态记忆；我们关注 agent 应该如何通过类型化、可执行、可验证的技能来操作记忆。M3-Agent 重点是 memory system；我们重点是 memory operation policy。

Related-work map（7 类，及我们在每类的位置）：

  1. A. Skill library / composition agents（Voyager、SayCan、Code as Policies）→ fixed typed skill basis + learned graph assembly。
  2. B. Neural-symbolic planning / program induction（LLM+P、NS-CL、program-of-thought）→ query → skill graph → evidence-grounded execution。
  3. C. VLM reasoning post-training（Visual-RFT、VLM-R1、Reason-RFT）→ 目标从自由文本 CoT 变成可执行 skill graph。
  4. D. Grounded reasoning / grounded CoT（Point-RFT、Argus）→ 句子级 → skill-node 级 grounding。
  5. E. Critic / self-correction / learn-from-failure（Critic-V）→ response correction → program repair。
  6. F. LLM verified RL / process reward（RLVR、PRM、VPR）→ 自由文本 step reward → typed node/edge/subgraph reward。
  7. G. Agent memory systems（M3-Agent、ReMEmbR、MemoryBank、HippoRAG、GraphRAG、MemGPT、LangMem）→ memory as storage/retrieval → memory as executable skill operations。

最强 paper positioning

展开完整描述

我们将长程多模态记忆推理表述为外部记忆基底上的神经符号技能组装问题。不同于训练紧凑模型直接回答长视频问题，我们训练它组装和修复可执行的 memory-skill programs，用来指导检索、验证和答案生成。Teacher demonstrations、benchmark ground-truth answers、evidence chains、executors 和 verifiers 提供监督与评测。我们将记忆从被动检索库转化为一个可执行的神经符号工作空间，并训练一个小 controller 来操作这个 workspace。

  • 最强一句话：我们不训练 8B 直接回答；我们训练它组装和修复可执行的 memory-skill graph，让 teacher / executors / verifiers 检索证据并到达 ground-truth answer。
  • 为什么更强：避开了拥挤的“又一个 memory graph”方向，且与 M3-Agent 式 memory system 有清楚区别。

评测 & 最强实验设定

展开完整描述

报告过程指标，而不只是流畅度。不要一开始覆盖所有 memory 操作——第一版聚焦三类任务：

  1. Task 1 — 长视频 memory QA：agent 能否查到过去事件、引用正确 evidence、回答跨时间问题？
  2. Task 2 — Memory update consistency：新观察进入后，memory 是否更新对、是否合并重复 entity、是否避免矛盾状态？
  3. Task 3 — Failure repair：给定错误检索 / 错误写入 / 错误时间链，能否通过 verifier feedback 修复？

Baseline：RAG over captions、GraphRAG、M3-Agent-like retrieval、CoT over retrieved memory、flat memory tools、linear memory-skill chain、ours（memory-skill graph）、ours + verifier / post-training。

指标：answer accuracy、evidence-chain recall / precision、retrieval correctness、hop / node success、trace correctness、memory-update validity、contradiction rate、abstention calibration、repair success、tool-call cost。

能让训练成立的实验：冻结 teacher-planner vs 训练后的 8B program controller，工具 + memory 相同；只有紧凑 policy 以更低成本达到相近 answer/evidence 质量，或 repair 更好、迁移更好、过程指标更好，它才被 justify。

备注：需要一个能评估 memory-operation correctness 的 benchmark，而不只是最终答案——见下一张卡片的候选数据集，以及它们仍然留下的 gap。

候选 benchmark 与 egocentric 聚焦

展开完整描述

这些部分填补了 benchmark gap（#3）——但没有完全填补。它们提供了很强的评测目标，部分还带 multi-hop / evidence 标注；但它们不提供 typed skill-graph trace 监督（node、arg、evidence pointer、temporal anchor），也不提供 memory-update / repair correctness 的评分。所以我们仍然需要在其上加一层轻量的 typed-trace + memory-operation 评测层——而这一层本身就可以是一等贡献。

Egocentric 长视频是天然的第一落点。第一人称、长程的视频流大量涉及 coreference、state tracking 和 social / theory-of-mind 推理——正是我们形式化的那些 memory 操作（“从我拿起手机到放进口袋之间，我跟谁说过话？”）。建议把第一篇锚定在 egocentric + social / temporal 多跳，而不是通用 web video。

映射到三类任务：

  1. 多跳证据 QA（Task 1）：LongVidSearch（multi-hop evidence reasoning）、Video-Holmes（复杂长程推理）。
  2. Social / ToM / temporal 推理：MA-EgoQA（social interaction、task coordination、theory-of-mind、temporal、environment）、Video-Holmes（social reasoning）。
  3. 长程 egocentric substrate / 数据源：EgoLife（长程第一人称数据，用于构建 memory store、update-consistency 和 repair 任务）。
  • 填补了：评测目标 + 部分 evidence-chain 标注（尤其 LongVidSearch）。
  • 仍然缺：typed skill-graph trace 标签 + memory-update / repair correctness 评分 → 自建一层薄的标注 / 评测层。
  • Scope 提示：web-agent video 大概率超出范围（不是 egocentric 持久记忆）；只作为 stretch 对比保留。
相关工作
  • Video-Holmes — 视频上复杂、长程的 social reasoning；多跳 social QA 的强目标。
  • EgoLife — 长程 egocentric 数据；构建 memory store / update / repair 任务的天然 substrate。
  • MA-EgoQA — Egocentric 的 social interaction、task coordination、theory-of-mind、temporal 与 environment interaction。
  • LongVidSearch — 长视频上的 multi-hop evidence reasoning；最接近 evidence-chain 监督。
  • Web-agent video — 可能超出范围；不是 egocentric 持久记忆——作为 maybe 保留。

推荐的第一篇收敛

展开完整描述

第一篇不要做所有 memory skills。聚焦 query + verify + reasoning over memory；把 store / update 作为辅助，不主打。

主贡献：

  1. 一个 typed memory-skill DSL。
  2. memory query / reasoning program 的神经符号组装。
  3. memory operations 上的 verifier-grounded 过程训练。
  4. 失败的 memory query / reasoning chain 的局部修复。

不要 claim：8B 是比 teacher 更强的长视频 reasoner。应该 claim：8B 学到一个可复用的 program-assembly and repair policy，用来组织 memory 上的检索、验证和答案生成。

留给第二篇：forgetting policy、memory compression、lifelong memory consolidation、diffusion memory field、fully autonomous memory evolution。

最终定位：不是新的 memory graph，也不是 8B long-video reasoner；而是一个紧凑 controller 借助 teacher demonstrations、ground-truth answers、evidence feedback 和 failure traces，学习组装与修复可执行的神经符号 memory programs。

ICLR readiness：framing 是使能条件，不是招牌

展开完整描述

这个 fix 的诚实边界。重写 framing 不提升研究本身的质量——它一行数据都没加。它是必要但不充分的：唯一作用是阻止一个好结果在 reviewer 头五分钟里被误判成“又一个 neural-symbolic / 又一个 memory graph”。预期效果约 +0.5～1 分，集中体现在不在 borderline 区间被误杀，而不是把 6 分抬成 8 分。如果两张 P0 表做不出来，framing 救不了论文；真实质量由实验决定。

Neural-symbolic = 地基，不是招牌。“neural-symbolic skill assembly” 是个老旗号（NS-CL、神经模块网络、ViperGPT、VisProg、LLM+P、program-of-thought）；用它当主标语会重新招来 novelty 归属攻击和“到底有多 symbolic？”的质疑（executor + soft verifier 都是 VLM）。把它当使能条件：正因为 memory 操作是带可检查 precondition / evidence pointer 的 typed symbolic operator，每一步才可验证——而这恰好是 failure-aware verified process RL + program repair 得以成立的前提，free-form CoT 做不到。

Headline 措辞（卖 RL + repair，把 NS 当“因为”）

Because memory operations can be cast as typed symbolic operators
with checkable preconditions and evidence pointers, every reasoning
step becomes verifiable. We exploit this to train a compact controller
with failure-aware verified process reward and program repair —
something free-form CoT cannot support.

动手实验前必须锁死的四个设计决策（这些是 framing / 设计问题，实验解决不了）：

  1. 一句话新意 = 在 typed memory ops 上的 failure-aware verified process RL + repair；把“skill graph”降级为载体。
  2. 三层 verifier，reward 只放 hard + anchor：hard（类型、时间戳、precondition、evidence pointer 是否存在、矛盾）+ benchmark anchor（answer correctness、evidence-chain recall）承担 reward；soft / teacher verifier 只作有噪声偏好，绝不进硬 reward。从结构上消除循环 / reward-hacking 质疑。
  3. 评测与监督解耦：生成 trace 的 teacher 不能当评分者；evidence-chain 用 benchmark 自带标注；自建 typed-trace eval 只评 hard 约束。
  4. 砍 scope 到 query + verify + repair over teacher 已建好的 memory；store / update / merge / forget / streaming 留给第二篇。

最小但致命的实验集（先把 P0 那一对当 go/no-go 闸门，再铺全量 pipeline）：

优先级实验要证明的命题
P0SFT-only vs + on-policy repair不是单纯 teacher 蒸馏
P0graph vs linear tool chain（同条件）图结构有可测收益
P1no-verifier ablationverified process RL 有用
P1vs M3-Agent / GraphRAG / CoT-over-retrieval打过强 baseline
P2cost / latency / teacher-fallback rate8B 真省钱
  • 最有区分度的指标：evidence-chain recall（抓“没接地但答对”的 teacher 路径）+ repair success rate（独特卖点）。
  • 是否抬高 neural-symbolic 的判定实验：no-symbolic-constraint / hard-verifier-off ablation——若符号检查带来可测收益（拦下的错误、减少的非法 program、使修复成为可能），NS 才配更响的角色；否则它只是 JSON-schema 校验，必须留作细节。
  • Go/no-go：若 on-policy repair 没明显超过 SFT-only，或 graph 没超过 linear chain，先重设故事，再投入全量 pipeline。

一句话：先锁四个设计决策，用两张 P0 表当闸门，再放大规模。Framing 移除的是埋没好结果的风险，而不是创造好结果。

用实质 reframe 提升真实质量(及它需要的实验)

展开完整描述

两种 reframe——只有一种能提升真实质量。

  1. 营销式 reframe(换说法):换 headline、把 neural-symbolic 降级、写更漂亮的 positioning。只改变别人的观感 → 不提升真实质量(见卡片 023)。
  2. 实质式 reframe(重定义研究问题 / 贡献单元):改变你测什么、claim 什么,从而改变你做哪些实验 → 这是除了跑实验之外唯一能提升真实质量的杠杆。没有免费午餐:它重定向努力,不替代努力——但能把同样的工作量瞄准更高的天花板。

四个实质 reframe(按杠杆排序):

  1. 从"做一个系统"到"研究一个现象"(最大杠杆)。不是"MemorySkillGraph 能做 memory reasoning",而是"什么时候、为什么 从失败的 memory program 学修复 会胜过蒸馏 / SFT?"把工程论文变成科学论文,产出是 finding 而不是 leaderboard 名次。
  2. 从"赢 benchmark"到"证明一个性质(property)"。瞄准 只有 typed-verifiable-repair 结构才能带来的 transfer / compositional generalization / reliability。property-centric framing 强迫你做出产生 principle 的实验——这是从 recipe 到 principle 的路。
  3. 从"repair 是一个阶段"到"repair 是中心对象"。把 bad program + feedback → repaired program 作为全篇深入研究的核心机制,而不是分散在五类 skill 上稀释。这是最不易被对标掉的 novelty;要集中。
  4. 从"自建 eval 是负担"到"评测协议是一等贡献"。"第一个能评分 memory-operation correctness + repair 的协议。"它的质量独立于方法是否赢 → 一条不依赖实验运气的质量下限。

推荐组合:主 reframe = #1 + #3(围绕 repair 机制的现象研究);#2 作为关键实验(transfer 证明);#4 作为质量保底(开源评测协议)。

需要加实验吗?需要——作为重定向,不是堆量。P0 那一对(卡片 023)仍是 go/no-go 闸门;在其上加下面这些 principle 级实验;砍掉任何只是"再来一张胜负表"的东西。净增约 +4,但要有纪律(每个 transfer / streaming 设置都很贵)。

Reframe新增实验(在卡片 023 之外)产出什么
#1 现象同预算 dose–response:repair-data vs SFT-data 的 scaling 曲线;on-policy vs offline 失败来源finding:何时 / 为何 repair > SFT
#2 性质短→长 & 离线→流式 transfer;留出 skill 组合的 compositional generalizationprinciple:结构带来 transfer
#3 repair 中心按 failure-code 的 repair 成功率;局部单节点修复 vs 整体重生成;repair 迁移到没见过的 failure type机制深度
可靠性相对强 baseline 的 hallucination / contradiction rate 下降可测量的可靠性收益
#4 benchmark协议可靠性:human–verifier 一致性、标注者间一致性、verifier false-accept rate评测有效性(不依赖胜负的质量下限)
  • 纪律:加实验只有在每个都能产出 finding 或 property 时才有用;纯增胜负表不提升真实质量。
  • 顺序:P0 闸门 → repair dose–response(#1/#3)→ transfer(#2)→ 可靠性 + 协议开源(#4)。

一句话:把这项工作从"一个会赢的 memory 系统"reframe 成"关于 repair-as-learning-signal 的现象研究,附带一个 transfer/可靠性性质和一套可复用评测协议"——同样的努力,换来天花板更高、且部分不依赖运气的产出。

开放问题

展开完整描述
  1. 最小稳定的 memory-skill 基底（跨五类）应该是什么？
  2. typed failure labels 和 program-repair 目标如何自动、廉价地生成？
  3. 如何让 verifier 足够可靠以避免 reward hacking？
  4. 在 EgoLife / LongVidSearch / Video-Holmes / MA-EgoQA 之上加一层薄的 typed-trace + memory-operation 评测层，能否评估 retrieval / update / repair correctness，而不只是最终答案？
  5. 一个重复且通过验证的 subgraph motif 何时应晋升为 composite memory skill？
  6. 8B program controller 在 inference time 仍需 teacher planning 前，能从 teacher demonstrations + ground-truth answer anchors + failure repair 中学到多少？
  7. 哪种 transfer 最能证明 claim：短 → 长视频，还是离线 → 流式记忆？
  8. Teacher compression 风险：如何证明 8B 不只是压缩 teacher plans？必需 ablation：teacher-only inference、8B SFT-only、8B + failure repair、8B + on-policy correction、graph vs linear chain、no-verifier、no-graph variants。
  9. Failure-data pipeline：bad program + feedback → repaired program 数据到底怎么造？候选方式包括 corrupt teacher traces、收集自然 8B rollout failures、执行 programs、分配 failure codes、让 teacher / human 给 repair targets，并做人工抽检。
  10. Verifier stack：能否明确拆成 hard verifiers（type、timestamp、precondition、evidence pointer 是否存在、contradiction）、benchmark anchors（answer correctness、evidence-chain recall）和 teacher / soft verifiers（有噪声的 preference / repair signal，不是 oracle）？
  11. Trace 非唯一性：如何避免把 teacher trace 当成唯一正确 graph？是否应该基于 answer、evidence chain、constraints、cost、unsupported-claim avoidance 定义 equivalence classes，而不是 exact trace match？
  12. Graph vs linear tool chain：什么可测假设能证明 graph structure 有用，而不是 JSON-CoT？候选 claim：branching、shared evidence、typed dependencies、局部 node/edge repair、sub-result caching、可复用 subgraph motifs。
  13. Cost model：把 controller calls、executor calls、verifier calls、retrieved-clip tokens 和 teacher fallback calls 都算进去后，8B 什么时候真的更便宜？fallback rate 多少时方法仍然经济？
  14. Executor boundary：第一篇哪些 skills 足够可靠、failure rate 是多少、repair 实际能修哪些错误？需要明确 perception failures（tracking、contact、speech/person linking、temporal boundaries）不是主要贡献。
  15. 第一篇 scope：是否应进一步收窄成 query + verify + repair over an existing teacher-built memory，把 store / update / merge / forget 留给第二篇？

备注：最紧急的方法问题是 failure-data generation pipeline 和非循环 verifier stack。最紧急的实验问题是证明 8B 不只是 teacher-plan compression，以及证明 graph structure 胜过 linear memory-tool chain。
